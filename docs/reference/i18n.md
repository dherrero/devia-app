# Internationalisation

Status: partial
Verified: b08bff62130756f1e2eb66ac2578efbef65c2823

- Engine: `@ngx-translate` (`I18nService`, `src/renderer/app/core/i18n/i18n.service.ts`). Files: `src/renderer/assets/i18n/<code>.json`, loaded on demand over HTTP.
- Shipped languages (`SUPPORTED_LANGUAGES`, `src/renderer/app/core/i18n/supported-languages.ts`): `es`, `en`, `ca` (Valencià), `fr`, `de`, `it`, `pt`, `ru`, `zh`, `hi`, `ar` = 11. Default `en`; OS locale detected until the user picks one; the choice is persisted as `language` in `devia-app.config.json`.
- Completeness (flattened keys, measured on this commit): `en` 1103, `es` 1103 (complete); `fr`, `ca`, `de`, `ar` 810 (293 missing); `hi`, `it`, `pt`, `ru`, `zh` 808 (295 missing). The old README said 10 languages and AGENTS.md says 11: 11 is right.
- A missing key does NOT fall back to English: `@ngx-translate` renders the raw key path (e.g. `sdd.event.task_done`).
- Parity gates: `tools/i18n-parity.test.ts` (ratchets: `COMPLETE_LANGUAGES` = `es` only; `PROTECTED_NAMESPACES` must match in every language, e.g. `app`, `codeGraph`, `diff_viewer`, `queue`, `splash`, `terminal`, `titlebar`), `tools/i18n-keys.test.ts`, `tools/i18n-code-graph-orphans.test.ts` (fails on unused `codeGraph.*` keys). Never remove an entry from the ratchets to make a build green.
- Plurals use the app-wide `key` / `key_plural` two-form convention (ru/ar get two forms only).
- Rules: every user-visible string goes through the `translate` pipe; error messages and some Telegram/clone strings emitted by main are Spanish literals in code.
